# OpenMP Sobel：任务划分、同步机制与性能分析

## 设计

同一张4096×4096灰度图，四种实现共享Sobel单行计算。内部4094行按64行一块划分成64个任务，最后一块62行。块间重叠读取真实输入邻行，各块独占输出行，不能把块接缝当成图像边界。

| 实现 | 映射与同步 |
|---|---|
| S 串行 | 按编号处理同一组任务，不创建工作线程 |
| P1 静态分块 | 按实际团队大小均分连续任务区间 |
| P2 锁任务池 | 锁保护共享编号的“取值并递增”，解锁后计算 |
| P3 原子任务池 | atomic capture完成相同领取操作，领取后计算 |

所有并行方案结束时隐式汇合。输入只读，输出区域不重叠，因此像素计算不加锁；共享领取编号需要同步。动态方案每次全图调用有64次成功领取，以及每线程一次终止领取。锁只保护极短的编号操作，不覆盖整个行块，更不覆盖整幅图。

`serial.cpp`、`parallel.cpp`提供可独立运行的入口；`sobel.hpp`定义核心与任务；`io.cpp`读写8位P5 PGM；`verify.cpp`执行参考卷积和任务所有权检查；`benchmark.cpp`执行正式测量和独立诊断；`run_experiment.py`生成固定输入、统计与绘图；`build_report.py`和`export_report.py`生成报告。

## 构建和单独运行

需要G++、Make和OpenMP。在本目录执行：

```bash
make -j4 all
make test
make sanitize
../../temp/bin/serial ../实验结果/固定输入灰度图.pgm ../../temp/serial_check.pgm
../../temp/bin/parallel ../实验结果/固定输入灰度图.pgm ../../temp/static_check.pgm 4 static
../../temp/bin/parallel ../实验结果/固定输入灰度图.pgm ../../temp/lock_check.pgm 4 lock
../../temp/bin/parallel ../实验结果/固定输入灰度图.pgm ../../temp/atomic_check.pgm 4 atomic
```

构建输出在仓库根目录`temp/bin`。单次命令行时间不是报告的预热后30次均值，不能混用。输入必须是最大灰度255的二进制P5 PGM；PNG只用于展示。

## 完整复现

实验脚本需要Python 3、NumPy、Pillow、Matplotlib和中文字体；依赖版本见`requirements.txt`。云环境已具备这些依赖和Noto CJK字体。若需隔离安装，可在`../../temp/venv`建立虚拟环境。

```bash
python3 run_experiment.py
```

此命令编译、执行普通及ASan/UBSan测试、验证实际团队大小、进行测量和诊断，再生成CSV及图表。**会覆盖本次数据，重新测量后须重新生成报告。**固定输入已有文件时先核对像素，避免无意替换。图像尺寸和块高不是性能实验变量。

报告生成需要`requirements-report.txt`中的包和LibreOffice：

```bash
python3 export_report.py
```

本地存在`../../temp/报告原始模版.docx`时复用上传模板；没有该文件时采用内置A4尺寸、中文字体和双栏正文设置。报告从当前CSV与元数据读取数值，作者、最后编辑者和PDF作者信息置空。封面学号、姓名和班级保留空白。字体使用Noto CJK以保证云端中文显示；生成后的分页仍应检查。

## 两项性能实验及理由

1. 固定4线程，对比串行和三种并行方案，观察任务分配设计的整体效果。
2. 各方案分别用1、2、4线程运行，比较扩展性、相对串行加速比与效率。

两项实验共享一次完整测量。共10种配置，各预热3次；正式30轮，每轮随机排列10种配置，种子20261025，共300条样本。统一`-O3 -std=c++17 -fopenmp -Wall -Wextra -Wpedantic`，不使用现成Sobel库函数。

环境固定`OMP_DYNAMIC=FALSE`、`OMP_PROC_BIND=close`、`OMP_PLACES=cores`、`OMP_WAIT_POLICY=PASSIVE`。可见5个逻辑CPU，但配额等效4核，因此主实验不使用8线程。

计时包含完整核心调用及共同配置分派、边界写入、线程运行时、领取、同步和锁生命周期；排除I/O、分配、比较和绘图。使用算术均值和样本标准差，不丢弃慢样本。加速比=串行均值/本组均值；效率=加速比/线程数。图中误差线为标准差，不是置信区间。

固定输入是自行生成的合成场景，所有测量组读取同一个PGM。输入SHA-256、C++源文件SHA-256、编译选项、环境及配额计数保存在`实验元数据.json`。

## 正确性与诊断

- 11种尺寸、5类输入；串行及3方案×4线程数×4块高：2695次独立参考比较。
- 2640次诊断所有权检查，覆盖块接缝、尾块、任务数少于线程数和不能整除的分配。
- 手算中心输出24；非法线程数、非法块高、输入输出别名检查。
- 普通和ASan/UBSan构建均通过。ASan/UBSan不是数据竞争检测器。
- 正式测量300次输出均与串行一致；独立诊断27次，所有任务均恰好被处理一次。

独立诊断每配置3次，保存每线程任务数、行数、领取次数及工作阶段时间，共63条线程记录。线程时间不包含末尾屏障等待，但包含被调度出去的时间；不能视为纯计算或纯锁耗时。诊断计数器和时钟调用在正式版本中通过编译期分支移除。报告任务分配图使用第1次诊断，全部3次数据均保留。
